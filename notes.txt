DevSecOps  means building security into every stage of the DevOps pipeline, automaticall, so security checks run as code 
on every commit instead of manual review at the end...

#### Core Principles:
     *************** 
           1- Shift left: catch issues early(in the IDE, on commit, in the PR ), where fixes are cheapest...
           2- Automate everything: security checks runin CI/CD, not in spreadsheets...
           3- Fails fast: block builds on HIGH or CRITICAL findings, and only warn on the rest...
           4- Everything as code: infrastructure , policies,and pipelines are all versioned and reviewed..
           5- Least privilege: apply it to pipeline, containers, cloud roles, and tokens..
           6- Shared ownership: developers own the fixes, and security provides tools and guardrails...

########### Pipeline Stages and Tools:
            *************************

pre-commit:  Scans secrets...it finds Leaked keys and password...Common tools: Gitleaks, TruffleHog 

builds:      SAST    ...it finds insecure code patterns...Common tools: Semgrep, SonarQube, CodeQL

Build:     SCA       ....it finds vulnerable dependencies...Common tools: Trivy, Snyk, OWASP, Dependency-Checks

Build: IaC scan      ...it finds cloud or k8s misconfigurations...Common tools: Checkov, tfsec, KICS

Package Container scan...it it finds Image CVEs...Common tools: Trivy, Grype

package  SBOM and signing...it finds Supply-chain integrity...Common tools: Syft, Cosign

Test     DAST        ...it finds Runtime vulnerabilities...Common tools: OWASP ZAP,Burp

Deploy    Policy as code ...it finds Non-compliant deployments...Common tools: OPA/Gatekeeper, kyverno

Runtime   Monitoring  ...it finds Attacks and anomalies...Common tools: Falco,SIEM 

DevSecOps Best Practices:
************************
    1- Store secrets in vault(HashiCorpVault,AWS Secrets Manager), never in code or environments files...
    2- Use OIDC instead  of long-lives cloud keys in CI...
    3- Pin GitHub Actions and base images to a SHA or digest , not latest, in production pipelines...
    4- set permissions: contents: read by default in workflows...
    5- Protect main with required reviews and required status checks...
    6- Enable Dependabot or Renovate fotfor automatic dependency updates...
    7- Generate and SBOM and sign every relerase image...
    8- Track findings centrally(DefectDojo, GitHub Security tab) with remediation SLAs, for example: Critical within 7 days, High within 30...
    9- Measure progress: mean time to renediate, open critical count, and the percentage of builds scanned...
